# Troubleshooting 403 Forbidden Errors

## Problem Description

Users are experiencing **403 Forbidden** errors when accessing the dashboard and other API endpoints, even though they are logged in. This typically happens after:

- Server restarts
- Backend configuration changes
- JWT secret changes
- Switching between different server instances

## Root Cause

The 403 errors are caused by **JWT token signature mismatch**. This happens when:

1. The authentication token was generated by a server with a different `JWT_SECRET`
2. The backend server was restarted with a new JWT secret
3. The user is connecting to a different server instance than the one that issued their token

## Quick Solution

### For Users:

1. **Clear your authentication and log in again:**
   - Visit: `http://localhost:3000/diagnostics`
   - Click "Clear Auth & Re-login"
   - Log in with your credentials again

2. **Or manually clear browser data:**
   - Open browser DevTools (F12)
   - Go to Application/Storage tab
   - Clear localStorage items:
     - `authToken`
     - `isLoggedIn`
     - `adminUser`
     - `staffUser`
     - `userType`
   - Refresh the page and log in again

### For Developers:

1. **Check if backend is running:**
   ```bash
   # Make sure your backend server is running on the correct port
   # Default: http://localhost:3000
   ```

2. **Verify API URL configuration:**
   ```bash
   # Check .env file
   cat APP/.env
   
   # Should match your backend server URL
   VITE_API_URL=http://localhost:3000/api
   ```

3. **Check backend JWT secret:**
   ```bash
   # Make sure JWT_SECRET is consistent in backend/.env
   # If you changed it, all existing tokens become invalid
   ```

## Common Scenarios

### Scenario 1: After Server Restart

**Symptoms:**
- 403 errors on all API calls
- "JWT signature mismatch" in console

**Solution:**
1. The server restarted with a different JWT secret
2. All existing tokens are now invalid
3. Users need to log in again to get new tokens

**Fix:** Clear auth and re-login

### Scenario 2: Wrong API URL

**Symptoms:**
- Network errors
- "Cannot reach server" messages
- All API calls fail

**Solution:**
1. Check `.env` file has correct `VITE_API_URL`
2. Verify backend server is running on that URL
3. Check for typos in the URL

**Fix:** Update `.env` and restart dev server

### Scenario 3: Permissions Issue

**Symptoms:**
- 403 errors on specific endpoints only
- Other endpoints work fine
- "Insufficient permissions" in console

**Solution:**
1. User account doesn't have permission for that resource
2. Sub-account with limited permissions
3. Role-based access control blocking access

**Fix:** Check user permissions in database or contact admin

## Prevention

### For Development:

1. **Use consistent JWT secrets:**
   ```bash
   # In backend/.env
   JWT_SECRET=your-consistent-secret-here
   
   # Don't change this unless necessary
   # If you must change it, inform all users to re-login
   ```

2. **Add JWT secret to version control (for dev only):**
   ```bash
   # For development, use a fixed secret
   # For production, use environment variables
   ```

3. **Implement token refresh:**
   ```javascript
   // TODO: Add refresh token mechanism
   // This allows tokens to be renewed without re-login
   ```

### For Production:

1. **Use long-lived JWT secrets**
2. **Implement refresh tokens**
3. **Add token expiration warnings**
4. **Graceful token renewal**
